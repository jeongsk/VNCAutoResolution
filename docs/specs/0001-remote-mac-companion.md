# 스펙: 원격 Mac 접속 도우미 (해상도 자동 변경 + 한/영 입력 동기화)

- 상태: ready-for-agent
- 작성일: 2026-10-09

## 용어

- **호스트 Mac**: 원격으로 접속받는 Mac(맥미니). macOS 화면 공유(VNC 서버, TCP 5900)가 켜져 있다.
- **클라이언트 Mac**: 접속하는 쪽 Mac(맥북). 화면 공유 앱 같은 뷰어로 호스트에 붙는다.
- **VNC 세션**: 호스트의 5900 포트에 들어온 연결(ESTABLISHED)이 하나 이상 있는 상태.
- **목표 해상도**: VNC 세션이 시작될 때 호스트에 적용할 해상도. 사용자가 고른다.
- **원래 해상도**: 세션 시작 직전 호스트의 해상도. 세션이 끝나면 이 해상도로 되돌린다.
- **피어**: 같은 앱을 실행 중인 다른 Mac.
- **페어링 암호**: 두 Mac에 같게 입력하는 비밀 문자열. 이 값으로 통신을 인증하고 암호화한다.
- **입력 소스**: macOS 키보드 입력 소스(예: 두벌식, ABC).
- **원격 세션 활성**: 입력 동기화가 동작해도 되는 상태. 로컬 VNC 세션이 있거나, 로컬에서 뷰어 앱이 실행 중이거나, 피어가 활성이라고 알려 온 경우다.

## Problem Statement

맥북에서 화면 공유(VNC)로 맥미니에 접속하면 맥미니의 해상도가 맥북 화면과 맞지 않습니다. 글자가 흐리거나 창이 너무 크거나 작습니다. 매번 맥미니의 시스템 설정에서 해상도를 직접 바꾸고, 접속을 끝낸 뒤 다시 되돌려야 합니다. 네트워크가 느려서 화면을 클라이언트에 맞춰 주는 화면 공유의 "고성능 모드"는 쓸 수 없습니다.

원격 접속 중에는 두 Mac의 한/영 입력 상태가 서로 어긋나기도 합니다. 그러면 한글이 자소 단위로 분리되어 입력되거나(`ㅎㅏㄴㄱㅡㄹ`), 글자 대신 Command 단축키가 실행됩니다. 사용자는 두 Mac의 입력 상태를 매번 손으로 맞춰야 합니다.

## Solution

두 Mac에 같은 메뉴바 앱 하나를 설치합니다.

- **호스트 Mac**: VNC 세션이 시작되면 미리 고른 목표 해상도로 자동 전환하고, 세션이 끝나면 원래 해상도로 되돌립니다.
- **두 Mac 모두**: 원격 세션 중에는 한/영 입력 소스를 양방향으로 실시간 동기화합니다. 한쪽에서 바꾸면 다른 쪽도 같은 상태가 됩니다.
- **연결**: 같은 공유기에서는 피어를 자동으로 찾습니다. 외부(Tailscale/VPN)에서는 상대 Mac 주소를 직접 입력해 연결합니다. 두 Mac에 같은 페어링 암호를 넣어야만 통신합니다.
- **역할 설정 없음**: 맥북에는 들어오는 5900 연결이 없으므로 해상도 기능이 저절로 동작하지 않습니다.

## User Stories

### 설치와 상주

1. 사용자로서, 같은 앱 하나를 맥북과 맥미니에 모두 설치하고 싶다. 역할별로 다른 앱을 관리하지 않기 위해서다.
2. 사용자로서, 앱이 Dock 없이 메뉴바에만 상주하길 원한다. 작업 공간을 차지하지 않게 하기 위해서다.
3. 사용자로서, 메뉴에서 "로그인 시 실행"을 켜고 싶다. 맥미니가 재부팅되어도 따로 실행하지 않아도 되도록 하기 위해서다.
4. 사용자로서, 메뉴바 아이콘만 보고 VNC 세션이나 동기화가 활성인지 알고 싶다. 앱이 동작 중인지 한눈에 확인하기 위해서다.
5. 사용자로서, 메뉴에서 앱을 종료하고 싶다.
6. 사용자로서, Apple Silicon과 Intel Mac 어느 쪽에서도 같은 앱이 실행되길 원한다. 맥미니 기종을 따지지 않기 위해서다.

### VNC 세션 감지

7. 맥미니 사용자로서, 맥북이 화면 공유로 접속하면 앱이 몇 초 안에 알아채길 원한다. 바로 해상도가 맞춰지게 하기 위해서다.
8. 맥미니 사용자로서, 메뉴에서 지금 접속한 클라이언트의 주소를 보고 싶다. 누가 접속했는지 확인하기 위해서다.
9. 맥미니 사용자로서, 네트워크가 잠깐 끊겼다 붙어도 세션이 끝난 것으로 처리되지 않길 원한다. 느린 네트워크에서 해상도가 왔다 갔다 하지 않게 하기 위해서다.
10. 맥북 사용자로서, 맥북에서 다른 Mac에 접속할 때(나가는 연결) 맥북 해상도가 바뀌지 않길 원한다.
11. 사용자로서, 여러 클라이언트가 동시에 접속해도 마지막 클라이언트가 나갈 때만 해상도가 복원되길 원한다.

### 해상도 자동 변경

12. 맥미니 사용자로서, 이 Mac이 지원하는 해상도 목록에서 목표 해상도를 고르고 싶다. 맥북 화면에 맞는 크기를 지정하기 위해서다.
13. 맥미니 사용자로서, 목록에서 HiDPI(Retina) 모드인지 구분해서 보고 싶다. 선명도와 크기를 고려해 고르기 위해서다.
14. 맥미니 사용자로서, VNC 세션이 시작되면 목표 해상도가 자동으로 적용되길 원한다.
15. 맥미니 사용자로서, VNC 세션이 끝나면 원래 해상도로 자동 복원되길 원한다. 맥미니에 직접 모니터를 연결해 쓸 때 문제가 없게 하기 위해서다.
16. 맥미니 사용자로서, 느린 네트워크에서는 낮은 목표 해상도를 골라 전송량을 줄이고 싶다.
17. 맥미니 사용자로서, "접속 시 자동 변경"을 끄고 켜고 싶다. 필요할 때 기능을 잠시 멈추기 위해서다.
18. 맥미니 사용자로서, 메뉴의 "지금 적용해 보기"로 목표 해상도를 미리 시험하고 싶다.
19. 맥미니 사용자로서, 메뉴의 "원래 해상도로 복원"으로 언제든 되돌리고 싶다.
20. 맥미니 사용자로서, 세션 도중 앱이 재시작되거나 꺼져도 다음 실행 때 원래 해상도가 복원되길 원한다. 해상도가 바뀐 채로 남지 않게 하기 위해서다.
21. 맥미니 사용자로서, 잠긴 화면이나 로그인 화면 상태에서 접속해 해상도 적용이 실패하면, 잠금을 풀었을 때 다시 시도되길 원한다.
22. 맥미니 사용자로서, 로그아웃하면 해상도 변경이 원래대로 돌아가길 원한다. 영구 설정이 망가지지 않게 하기 위해서다.
23. 맥미니 사용자로서, 해상도 변경이나 복원이 실패하면 메뉴에서 이유를 보고 싶다.
24. 모니터 없는 맥미니 사용자로서, 쓸 수 있는 해상도가 적으면 그 사실을 알고 싶다. 더미 플러그나 가상 디스플레이 도구가 필요한지 판단하기 위해서다.
25. 맥미니 사용자로서, 디스플레이가 바뀌면(모니터나 더미 플러그 연결·해제) 해상도 목록이 자동으로 갱신되길 원한다.

### 피어 연결과 페어링

26. 사용자로서, 두 Mac에 같은 페어링 암호를 입력해 연결하고 싶다. 내 Mac끼리만 통신하게 하기 위해서다.
27. 사용자로서, 페어링 암호가 다른 기기와는 연결 자체가 거부되길 원한다. 같은 네트워크의 다른 사람이 내 입력 상태를 바꾸지 못하게 하기 위해서다.
28. 사용자로서, 같은 공유기에서는 주소 입력 없이 피어를 자동으로 찾고 싶다.
29. 사용자로서, 외부 네트워크(Tailscale/VPN)에서는 상대 Mac의 주소(호스트명이나 IP)를 직접 입력해 연결하고 싶다.
30. 사용자로서, 같은 피어가 자동 탐색과 직접 입력 양쪽으로 잡혀도 하나의 피어로 취급되길 원한다. 메시지가 중복되지 않게 하기 위해서다.
31. 사용자로서, 연결이 끊기면 앱이 자동으로 다시 연결하길 원한다.
32. 사용자로서, 메뉴에서 연결된 피어의 이름과 연결 경로(자동 탐색/직접 입력)를 보고 싶다.
33. 사용자로서, 처음 실행할 때 "로컬 네트워크 접근" 권한이 왜 필요한지 안내받고 싶다.
34. 사용자로서, 느린 네트워크에서도 동기화 메시지가 즉시 전달되길 원한다. 메시지가 아주 작기 때문이다.

### 한/영 입력 동기화

35. 사용자로서, 원격 세션 중 한쪽 Mac에서 한/영을 바꾸면 다른 Mac도 같은 상태로 바뀌길 원한다. 자소 분리를 막기 위해서다.
36. 사용자로서, 화면 공유 창에서 한/영 키를 누를 때 어느 Mac이 먼저 바뀌든 결국 두 Mac이 같은 상태가 되길 원한다.
37. 사용자로서, 동기화가 서로를 계속 바꾸는 무한 반복(에코 루프)이 생기지 않길 원한다.
38. 사용자로서, 한/영을 빠르게 연달아 바꿔도 마지막 상태가 정확히 반영되길 원한다.
39. 사용자로서, 두 Mac의 한글 입력기가 달라도(예: 두벌식과 구름입력기) 언어 기준으로 맞춰지길 원한다.
40. 사용자로서, 영문 입력기가 달라도 ABC를 우선으로, 없으면 다른 비한국어 입력기로 맞춰지길 원한다.
41. 사용자로서, 기본 설정에서는 원격 세션 중에만 동기화되길 원한다. 평소에 각 Mac을 따로 쓸 때 입력 상태가 바뀌지 않게 하기 위해서다.
42. 사용자로서, 원하면 "항상 동기화"로 바꾸고 싶다.
43. 맥북 사용자로서, 화면 공유·Screens·Jump Desktop 같은 뷰어 앱이 실행 중이면 원격 세션 중으로 인식되길 원한다.
44. 맥미니 사용자로서, VNC 세션이 들어와 있으면 원격 세션 중으로 인식되길 원한다.
45. 사용자로서, 원격 세션이 시작되면 뷰어를 보는 쪽(클라이언트 Mac)의 입력 상태로 상대가 한 번 맞춰지길 원한다. 시작부터 상태를 일치시키기 위해서다.
46. 사용자로서, 메뉴에서 입력 동기화를 일시정지하고 재개하고 싶다.
47. 사용자로서, 메뉴에서 지금 입력 상태(한/A)와 동기화 상태(활성/대기/일시정지)를 보고 싶다.

### 배포와 표기

48. 사용자로서, 빌드 스크립트 한 번으로 서명된 `.app`을 만들고 싶다. 두 Mac에 복사해 설치하기 위해서다.
49. 사용자로서, 다른 Mac에서 빌드한 앱을 옮겼을 때 Gatekeeper 경고를 푸는 방법을 안내받고 싶다.
50. 오픈소스 이용자로서, 참고한 오픈소스(HangulSync, MIT)의 저작권 고지가 앱 저장소에 남아 있길 원한다.

## Implementation Decisions

### 전체 구조

- 앱은 하나의 SwiftUI 메뉴바 앱(`MenuBarExtra`)입니다. 대상은 macOS 13 이상이고 Apple Silicon과 Intel 겸용(universal) 바이너리로 만듭니다.
- 역할 설정은 없습니다. 해상도 기능은 들어오는 5900 연결이 있을 때만 동작하므로 클라이언트 Mac에서는 저절로 꺼진 상태가 됩니다.
- 순수 로직은 **앱 코어** 하나에 모읍니다. OS와 맞닿는 부분은 모두 포트(프로토콜)로 주입합니다. UI는 코어의 상태를 보여 주고 사용자 조작을 코어로 넘기기만 합니다.

### 앱 코어 (테스트 seam ①)

코어는 이벤트를 받아 상태를 바꾸고, 포트에 명령을 내립니다. 시간과 폴링 주기도 주입해서 테스트에서 직접 조정할 수 있게 합니다.

주입되는 포트:

- **VNC 감지 포트**: 현재 VNC 클라이언트 주소 목록을 돌려줍니다.
  - 실제 구현은 `nettop -m tcp -L 1 -n -J state` 출력에서 로컬 포트가 5900이고 상태가 Established인 줄을 찾습니다. macOS 27부터 `netstat`이 TCP 소켓을 보여 주지 않기 때문입니다. 이전 macOS를 위해 `netstat -an -p tcp` 결과도 합칩니다.
- **디스플레이 포트**: 사용 가능한 해상도 목록, 현재 해상도, 해상도 적용(성공/실패)을 제공합니다.
  - 실제 구현은 CoreGraphics 공개 API를 씁니다.
  - 중복 저해상도 모드까지 포함해 나열하고, 데스크톱에 쓸 수 있는 모드만 남깁니다.
  - 같은 크기면 가장 높은 주사율을 고릅니다.
  - 변경은 세션 범위(`forSession`)로만 적용합니다.
- **입력 소스 포트**: 현재 입력 소스(ID, 한국어 여부)를 조회하고 입력 소스를 적용합니다. 로컬 입력 소스가 바뀌면 코어에 알립니다.
  - 정확히 같은 ID가 없으면 언어 기준으로 대체합니다. 한국어면 첫 한국어 입력기, 영문이면 ABC, 그다음 비한국어 입력기 순입니다.
  - 변경 알림은 TIS 입력 소스 변경 분산 알림으로 받습니다.
- **뷰어 앱 감지 포트**: 로컬에서 원격 데스크톱 뷰어 앱이 실행 중인지 알려 줍니다(번들 ID 접두사 목록).
- **피어 전송 포트**: 연결된 피어에게 메시지를 보내고, 받은 메시지와 피어 연결·해제를 코어에 전달합니다.
- **설정 저장소 포트**: 아래 값을 저장합니다.
  - 자동 변경 사용 여부, 목표 해상도 ID, 원래 해상도 ID
  - 동기화 사용 여부, 원격 세션 중에만 동기화 여부
  - 직접 입력한 피어 주소, 기기 ID
  - 페어링 암호는 Keychain에 저장합니다.
- **시계**: 현재 시각을 제공합니다.

해상도 상태 머신:

- 상태는 `대기`, `세션 중(적용됨)`, `세션 중(적용 대기·재시도)`입니다.
- `대기`에서 VNC 클라이언트가 처음 보이면 다음을 합니다.
  - 자동 변경이 켜져 있고 목표 해상도가 정해져 있을 때만 동작합니다.
  - 원래 해상도가 아직 저장되지 않았다면 현재 해상도를 원래 해상도로 저장합니다.
  - 목표 해상도를 적용합니다.
- 적용이 실패하면(잠긴 화면 등) 세션이 이어지는 동안 일정 간격으로 재시도하고, 최대 횟수를 둡니다. 재시도할 때마다 해상도 목록을 다시 읽습니다.
- 클라이언트 목록이 연속 2회(약 4초) 비면 세션 종료로 판단합니다. 그때 원래 해상도를 복원하고 저장값을 지웁니다.
- **시작 시 복원**: 앱이 시작될 때 원래 해상도가 저장되어 있는데 VNC 세션이 없으면 즉시 복원합니다.
- "지금 적용해 보기"도 원래 해상도가 없으면 먼저 저장합니다. 그래야 "원래 해상도로 복원"이 항상 가능합니다.

입력 동기화 규칙:

- 메시지는 항상 **절대 상태**(입력 소스 ID와 한국어 여부)를 보냅니다. "토글" 메시지는 쓰지 않습니다.
- **에코 억제**는 "방금 원격 상태로 적용한 입력 소스 ID"를 기준으로 합니다.
  - 로컬 변경 알림이 오면, 그 ID가 방금 적용한 ID와 같고 짧은 유효시간 안이면 전파하지 않습니다.
  - 다른 ID로 바뀌었다면 시간 창 안이라도 사용자의 실제 전환으로 보고 전파합니다.
- 받은 상태가 현재 로컬 상태와 같으면 아무것도 하지 않습니다.
- 동기화 허용 조건은 다음과 같습니다.
  - 동기화가 켜져 있어야 합니다.
  - "원격 세션 중에만"이 꺼져 있으면 항상 허용합니다.
  - 켜져 있으면 로컬 VNC 세션, 로컬 뷰어 앱 실행, 피어의 세션 활성 신호(유효시간 내) 중 하나라도 있어야 합니다.
- 로컬 원격 세션이 시작되면 세션 활성을 알리고 현재 입력 상태를 한 번 보냅니다.
- 세션 활성 신호는 주기적으로 다시 보내고, 유효시간이 지나면 만료됩니다.

### 피어 프로토콜과 전송 (테스트 seam ②)

- 전송은 Network.framework TCP를 씁니다. 지연과 연결 유지를 위해 다음을 설정합니다.
  - Nagle 끄기(noDelay)
  - keepalive 켜기(idle 약 30초)
  - 연결 타임아웃 약 5초
  - 응답성 우선 서비스 클래스
- 보안은 **TLS-PSK**입니다. 키는 페어링 암호에서 파생합니다(HMAC 기반). Apple TicTacToe 샘플 방식대로 최대 버전을 TLS 1.2로 고정하고 PSK 암호 스위트를 씁니다. 암호가 다르면 핸드셰이크가 실패해야 합니다.
- 메시지는 줄바꿈으로 구분한 JSON입니다. 종류는 세 가지입니다.

  ```
  hello   { deviceID, name, protocolVersion }
  input   { deviceID, sourceID, isKorean }
  session { deviceID, active }
  ```

- 연결이 열리면 양쪽이 먼저 `hello`를 보냅니다. **같은 피어인지는 연결 주소가 아니라 deviceID로 판단**하고, 같은 deviceID의 중복 연결은 하나만 남깁니다. 자기 자신의 deviceID는 무시합니다.
- **탐색**: 고정 포트로 리스너를 열고, 고유 서비스 타입으로 Bonjour 광고와 탐색을 합니다. Bonjour로 찾은 피어는 서비스 이름이 사전순으로 작은 쪽이 연결을 겁니다(양방향 중복 연결 방지). 직접 입력한 주소는 입력한 쪽이 항상 연결을 시도합니다.
- 끊긴 연결은 백오프 간격으로 다시 연결합니다.
- 보내는 메시지 크기와 빈도를 제한해서, 비정상적인 피어가 보내는 메시지는 무시합니다.

### 앱 번들과 배포

- 빌드 스크립트가 SwiftPM 릴리스 빌드(universal)로 `.app` 번들을 만들고 ad-hoc 서명합니다.
- Info.plist에는 번들 ID, `LSUIElement`, 로컬 네트워크 사용 설명(`NSLocalNetworkUsageDescription`), Bonjour 서비스 타입(`NSBonjourServices`)을 넣습니다. 이 항목이 없으면 macOS 15 이상에서 탐색과 리스너가 조용히 실패합니다.
- 로그인 시 실행은 `SMAppService.mainApp`을 씁니다. 번들로 실행할 때만 동작합니다.
- 로컬 네트워크 권한은 코드 서명에 묶여 있어서, ad-hoc으로 다시 빌드하면 권한을 다시 물을 수 있다고 README에 적습니다.
- HangulSync에서 옮겨 온 로직(입력 소스 대체 규칙, 에코 억제, TCP 튜닝)에 대해 MIT 저작권 고지를 별도 고지 파일에 남깁니다.

### UI(메뉴)

- 상태 표시: VNC 세션 여부와 클라이언트 주소, 현재 해상도, 입력 상태(한/A), 동기화 상태, 연결된 피어, 마지막 메시지(오류 포함)
- 해상도 항목: 접속 시 자동 변경 토글, 목표 해상도 선택, 지금 적용해 보기, 원래 해상도로 복원
- 동기화 항목: 동기화 일시정지/재개, 원격 세션 중에만 동기화 토글
- 설정 창: 페어링 암호, 직접 연결할 피어 주소
- 기타: 로그인 시 실행, 종료

## Testing Decisions

- 좋은 테스트는 **외부 동작만 검증**합니다. 이벤트를 넣고 그 결과로 포트에 내려진 명령(해상도 적용·복원, 입력 소스 적용, 메시지 전송)과 공개 상태를 확인합니다. 내부 필드나 메서드 호출 순서는 검증하지 않습니다.
- 테스트 seam은 두 개입니다.
  1. **앱 코어**: 가짜 포트(VNC 감지, 디스플레이, 입력 소스, 뷰어 감지, 피어 전송, 저장소, 시계)를 주입합니다. 다음 시나리오를 검증합니다.
     - 세션 시작 시 목표 해상도 적용과 원래 해상도 저장
     - 한 번만 비는 폴링에는 복원하지 않고, 연속 두 번 비면 복원
     - 자동 변경이 꺼져 있거나 목표가 없으면 아무것도 하지 않음
     - 적용 실패 후 재시도, 최대 횟수 도달
     - 앱 시작 시 저장된 원래 해상도 복원
     - 여러 클라이언트 중 마지막 클라이언트가 나갈 때만 복원
     - 로컬 입력 변경 시 절대 상태 메시지 전송
     - 원격 상태 적용 후 같은 ID 에코는 억제, 다른 ID로의 빠른 실제 전환은 전파
     - 이미 같은 상태면 적용하지 않음
     - 정확한 ID가 없을 때 언어 기준 대체 결과
     - 세션 게이트(로컬 VNC, 뷰어 앱, 피어 신호와 유효시간 만료, 항상 동기화 옵션)
     - 세션 시작 시 현재 상태 1회 전송
     - 같은 deviceID 중복 연결 정리, 자기 메시지 무시
     - nettop·netstat 출력 파싱(IPv4/IPv6, 들어오는 연결과 나가는 연결 구분)
  2. **피어 전송(loopback 통합 테스트)**: localhost에 리스너와 클라이언트를 띄웁니다.
     - 같은 페어링 암호면 연결되고 메시지가 왕복합니다.
     - 다른 암호면 핸드셰이크가 실패합니다.
     - 줄바꿈 JSON 메시지가 잘리거나 합쳐져 도착해도 올바르게 분리됩니다.
- 실제 디스플레이·입력 소스 변경과 두 Mac 사이의 전체 흐름은 자동 테스트하지 않습니다. 대신 README에 **두 Mac 수동 테스트 체크리스트**를 둡니다.
  - 접속하면 해상도가 바뀌고, 끊으면 복원되는지
  - 잠긴 화면에서 접속했을 때 재시도되는지
  - 한/영이 양방향으로 맞춰지는지
  - 외부 주소로 연결되는지
  - 잘못된 암호가 거부되는지
- 기존 테스트 선례는 이 저장소에 없습니다. 참고할 외부 선례는 HangulSync의 프로토콜 보안 테스트와 페어링 테스트(XCTest)입니다. 테스트 프레임워크는 XCTest 또는 Swift Testing 중 툴체인이 지원하는 것을 씁니다.

## Out of Scope

- 클라이언트 Mac의 화면 크기를 자동으로 알아내 해상도를 맞추는 기능. 목표 해상도는 사용자가 고릅니다.
- 비공개 API가 필요한 기능
  - 가상 디스플레이 생성(`CGVirtualDisplay`)
  - "다이내믹 해상도" 켜기(SkyLight)
  - 디스플레이 끄기
- 화면 공유 고성능 모드 지원, 고성능 모드의 가상 디스플레이 제어
- HangulSync의 인터넷 릴레이(ntfy), 공개키 기반 기기 신원·Keychain 신원, 초대 코드/랑데부, Tailscale 자동 탐색, 다국어 UI, 업데이트 확인
- remote-input-sync의 Karabiner 규칙과 SSH 스크립트. 같은 목적을 양방향 동기화로 달성합니다.
- 클립보드 동기화 등 다른 원격 편의 기능
- Windows/Linux 클라이언트
- App Store 배포, 공증(notarization)

## Further Notes

- **조사 결과**(2026-10-09):
  - [bhicks329/resolution-fixer](https://github.com/bhicks329/resolution-fixer)는 같은 방식(5900 포트 감시)으로 해상도를 자동 변경합니다. 라이선스가 없어 코드는 가져오지 않고 아이디어만 참고했습니다(잠긴 화면 재시도, 시작 시 복원).
  - 이 도구는 SkyLight 비공개 API로 다이내믹 해상도도 켭니다. 일반(비고성능) 화면 공유에서도 해상도가 창 크기를 따라간다면 "목표 해상도 수동 선택"이 필요 없어집니다. 다만 Apple 문서는 다이내믹 해상도가 고성능 연결 전용이라고 합니다. 이 도구로 실제 동작을 먼저 확인하고, 동작하면 후속 스펙에서 선택 기능으로 추가를 검토합니다.
  - 모니터 없는 맥미니에서 해상도 선택지가 부족하면 HDMI 더미 플러그, [SimpleDisplay](https://github.com/SamuelRioTz/SimpleDisplay)(GPL-3.0), [DeskPad](https://github.com/Stengo/DeskPad)를 함께 쓰도록 안내합니다.
  - 입력 동기화는 [HangulSync](https://github.com/catgarret/HangulSync)(MIT)의 접근을 단순화해 옮깁니다. [remote-input-sync](https://github.com/firejune/remote-input-sync)(MIT)는 같은 문제를 Karabiner와 SSH로 풉니다. 이 스펙에서는 쓰지 않습니다.
- 현재 저장소에는 해상도 기능의 초기 구현(감지, 디스플레이 변경, 메뉴)이 있습니다. 하지만 포트 주입 구조와 시작 시 복원이 없어 이 스펙에 맞게 재구성해야 합니다.
- 입력 소스 전환(`TISSelectInputSource`)은 LSUIElement 앱이나 비활성 앱에서 가끔 반영되지 않는다는 보고가 있습니다. 구현할 때 HangulSync의 처리와 릴리스 노트를 확인하고, 필요하면 적용 직후 재확인하고 다시 시도합니다.
