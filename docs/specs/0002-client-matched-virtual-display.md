# 스펙: 클라이언트 화면에 맞춘 가상 디스플레이

- 상태: ready-for-agent
- 작성일: 2026-10-09
- #1의 Out of Scope 중 "가상 디스플레이 생성(`CGVirtualDisplay`)" 항목을 이 스펙으로 대체한다.

## Problem Statement

모니터가 없는 맥미니에서 고를 수 있는 해상도는 1920×1080 하나뿐이다. 그래서 #3의 "목표 해상도" 기능으로는 맥북 화면에 맞출 수 없다. 사용자는 맥북으로 VNC 접속하면 맥미니 화면이 맥북 화면 크기와 정확히 같아지길 원한다.

## Solution

두 Mac은 이미 피어로 연결되어 있다(#4). 클라이언트 Mac(맥북)의 앱이 자기 화면 크기를 호스트 Mac(맥미니)에 보낸다.

호스트 Mac은 VNC 세션 중에 그 크기의 **가상 디스플레이**를 만든다. 세션이 끝나면 가상 디스플레이를 없앤다.

### 실측 결과 (2026-10-09, Mac mini, macOS 27.0.1, 헤드리스)

- 가상 디스플레이를 만들면 기존 1920×1080 기본 화면이 온라인 목록에서 사라진다. 가상 디스플레이가 유일한 메인 화면이 된다. 메인 지정이나 미러링은 필요 없다.
- 사용자가 맥북 화면 공유(일반 모드) 창에서 직접 확인했다. 화면 하나가 1512×982 크기로 바뀌어 보였다.
- 가상 디스플레이를 만든 프로세스가 끝나면 원래 화면으로 돌아온다.
- 가상 디스플레이의 `CGDisplayCopyDisplayMode`는 nil을 돌려줬다. 반면 `CGDisplayBounds`는 정확했다.

## User Stories

1. 맥북 사용자로서, 맥미니에 VNC로 접속하면 맥미니 화면이 내 맥북 화면 크기와 똑같아지길 원한다. 글자와 창 크기가 자연스럽게 보이게 하기 위해서다.
2. 맥미니 사용자로서, 접속이 끝나면 가상 디스플레이가 사라지고 원래 화면으로 돌아가길 원한다.
3. 맥미니 사용자로서, 앱이 비정상 종료돼도 화면이 원래대로 돌아오길 원한다.
4. 맥북 사용자로서, 맥북의 화면 크기(해상도 설정, 외부 모니터 이동)가 바뀌면 맥미니도 따라 바뀌길 원한다.
5. 맥미니 사용자로서, 메뉴에서 "클라이언트 화면에 맞추기"를 켜고 끄고 싶다.
6. 맥미니 사용자로서, 느린 네트워크를 고려해 기본은 1배율(비 HiDPI)로 만들고, 원하면 HiDPI를 켜고 싶다.
7. 맥미니 사용자로서, 메뉴에서 받은 클라이언트 화면 크기와 가상 디스플레이 상태(사용 중/대기/사용 불가)를 보고 싶다.
8. 맥미니 사용자로서, macOS가 이 기능을 지원하지 않으면 앱이 죽지 않고 "사용 불가"만 표시되길 원한다. 해상도와 입력 동기화 기능은 계속 써야 하기 때문이다.
9. 맥미니 사용자로서, 화면 공유 고성능 모드의 가상 디스플레이가 이미 있으면 이 기능이 끼어들지 않길 원한다.
10. 맥미니 사용자로서, 가상 디스플레이를 쓰는 동안 기존 "목표 해상도" 기능이 엉뚱한 화면에 해상도를 적용하지 않길 원한다.
11. 맥미니 사용자로서, 피어 정보가 없으면(맥북 앱 미실행) 기존 "목표 해상도" 기능으로 동작하길 원한다.

## Implementation Decisions

### 클라이언트 화면 정보 전송

- 새 피어 메시지는 `display { deviceID, width, height, scale }`이다. width·height는 포인트 단위, scale은 배율이다.
- 보내는 쪽은 **뷰어 앱이 실행 중인 쪽**뿐이다.
  - 세션이 시작될 때, 피어가 새로 연결될 때, 화면 구성이 바뀔 때 메인 화면 크기를 보낸다.
  - 화면 구성 변경은 `NSApplication.didChangeScreenParametersNotification`으로 감지한다.
- 코덱은 모르는 메시지 종류를 받아도 연결을 끊지 않고 무시해야 한다. 구 버전과 섞여 있을 때를 대비한다.
- 호스트는 클라이언트 화면 정보를 이렇게 정한다. 세션 신호가 활성인 피어가 보낸 **가장 최근** `display` 정보를 쓴다.
  - VNC 클라이언트 IP와 피어 주소는 서로 맞춰 보지 않는다. 피어 연결은 링크 로컬 `fe80::`로, VNC는 `192.168.x.x`로 잡히기 때문이다.
  - 여러 클라이언트가 동시에 접속하는 경우는 다루지 않는다.

### 가상 디스플레이 컨트롤러 (코어, 순수 로직)

- 새 포트 `VirtualDisplayControlling`이 다음을 제공한다.
  - 사용 가능 여부
  - 생성(width, height, hiDPI)과 모드 변경
  - 제거
  - 고성능 화면 공유 가상 디스플레이가 있는지 여부
- 생성 조건은 모두 만족해야 한다.
  - 기능이 켜져 있다.
  - 로컬 VNC 세션이 있다.
  - 클라이언트 화면 정보가 있다.
  - 포트가 사용 가능하다.
  - 고성능 가상 디스플레이가 없다.
- 세션 종료 판단은 해상도 컨트롤러와 같은 디바운스(연속 2회 미감지)를 쓴다. 종료되면 제거한다.
- 클라이언트 화면 정보가 바뀌면 모드를 바꾼다.
- 모드는 1배율일 때 포인트 크기 그대로(w×h) 만든다. HiDPI가 켜져 있으면 픽셀 w·scale × h·scale로 만들고 HiDPI로 설정한다.
- **해상도 컨트롤러와의 관계**: 가상 디스플레이가 있는 동안 `ResolutionController`는 멈춘다(적용·복원·재시도·디스플레이 변경 반영 모두). 세션이 시작될 때 클라이언트 화면 정보가 있고 기능이 켜져 있으면 가상 디스플레이가 우선한다. 없으면 기존 목표 해상도로 동작한다. 이 우선순위와 상호 배제를 코어 테스트로 검증한다.
- 설정: "클라이언트 화면에 맞추기"(기본 켬)와 "HiDPI 가상 디스플레이"(기본 끔)를 UserDefaults에 저장한다.

### 어댑터 (앱 타깃, 비공개 API)

- `CGVirtualDisplay`, `CGVirtualDisplayDescriptor`, `CGVirtualDisplaySettings`, `CGVirtualDisplayMode`는 **런타임에** `NSClassFromString`으로 찾는다. 필요한 셀렉터가 있는지 확인한 뒤 쓴다. 링크 시점에 참조하지 않는다. 클래스가 없으면 "사용 불가"가 되고 앱은 계속 동작한다.
- 가상 디스플레이 객체는 어댑터가 강한 참조로 보관한다. 참조를 놓으면 제거된다. 프로세스가 끝나면 시스템이 자동으로 정리한다.
- 가상 디스플레이를 다른 화면의 미러로 만들지 않는다. WindowServer가 죽는다는 보고가 있다.
- 고성능 세션의 가상 디스플레이는 `NSScreen.localizedName`에 "Screen Sharing Virtual Display"가 있는지로 감지한다. 관련 문제는 BetterDisplay #5860에 보고되어 있다.
- 헤더 선언은 DeskPad(MIT)를 참고한다. `THIRD_PARTY_NOTICES.md`에 DeskPad 고지를 추가한다. SimpleDisplay(GPL)의 코드는 쓰지 않는다.

## Testing Decisions

- 코어 테스트는 가짜 `VirtualDisplayControlling`, 가짜 피어 전송, FakeClock을 쓴다. 다음 시나리오를 검증한다.
  - 생성 조건 조합
  - 디바운스 후 제거
  - 화면 정보 변경 시 모드 변경
  - HiDPI 픽셀 계산
  - 사용 불가일 때와 고성능 가상 디스플레이가 있을 때 생성하지 않음
  - 해상도 컨트롤러 정지와 상호 배제
  - 정보가 없을 때 목표 해상도로 대체
  - `display` 메시지 송신 조건(뷰어 쪽만)
  - 모르는 메시지 종류를 무시하고 연결 유지
- 실제 가상 디스플레이 생성은 자동 테스트하지 않는다. README 수동 체크리스트에 추가한다.

## Out of Scope

- 클라이언트 여러 대 동시 지원
- 외부 모니터나 더미 플러그가 연결된 호스트에서 가상 디스플레이를 메인으로 지정하거나 기존 화면을 미러링하는 것(실측 결과 헤드리스에서는 필요 없음)
- 고성능 모드 지원
- 가상 디스플레이에 쓸 수 있는 해상도 목록 UI

## Further Notes

- 비공개 API라서 macOS 업데이트 때 깨질 수 있다. 런타임 확인으로 앱 전체가 멈추는 일만은 막는다.
- 가상 디스플레이의 `CGDisplayCopyDisplayMode`가 nil일 수 있다. 상태 표시에는 `CGDisplayBounds`를 쓴다.
